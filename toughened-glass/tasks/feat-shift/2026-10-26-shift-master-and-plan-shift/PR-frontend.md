# 2026-10-26 - shift-master-and-plan-shift (frontend)

## Summary

There was no Shift page in Master Data, and the Create Production Plan table asked for a start date and an end date per line. This PR adds a Shift page built the same way as Charges (Active, Inactive and All tabs, KPI cards, search, add, edit, deactivate, delete, view details) with a start and end time. In the production plan table, Start and End are replaced by one Date and a Shift dropdown. The dropdown is a reusable component that reads the active shifts from Master Data and can add a new shift without leaving the plan.

**Opening these screens in a browser is not included on purpose** - see "Notes" below. This was a choice, not a miss.

## Why

Plans are made per day and per shift. A shift needs to be maintained in one place and picked from a list, and the person planning should not have to leave the plan to add one that is missing.

## How

**Shift page**: same layout and behaviour as Charges, so users find it familiar. The status toggle, deactivate and delete use the same dialogs.

**Shift dropdown**: `ShiftSelect` loads the shift list once (cached for 5 minutes) and shows only active shifts. If a saved line points to a shift that is now inactive, it is still shown by its name so the line does not look empty.

**Add from the dropdown**: the "+ Add New Shift" item shows only for users with `master_shift` CONTROL. It opens the same form as the Shift page. After saving, the new shift is selected on that line.

**Kept the same on purpose**: Work Centre, Planned Qty and Remarks columns, and the save, submit, approve and reject flow, did not change.

## Decisions made

**Shift is optional on a plan line.** The old dates were optional too. Making it required was left for the team to decide.

**A shared time picker instead of the browser time input.** It matches the other custom pickers and shows 12 hour time.

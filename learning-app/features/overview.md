# Features Overview

A concise summary of implemented features across all four project parts: Mobile App, Backend, Web App, and Admin Panel.

> **How to maintain:** When a new feature is added, insert a single row into each of the four tables below, and add the full deep-dive explanation into its corresponding developer guide under `features/<feature-name>/`.

---

## 1. Mobile App

| Feature | Explanation | API Endpoints | Database Tables |
|---|---|---|---|
| **Sign Up** | Guides students or parents through test choice, experience, name, and contact details. Stores input in a local draft context and submits to create a passwordless mobile account. | `POST /api/v1/auth/register` | `users`<br>`user_exam_preferences` |
| **Login** | Authenticates students and parents using 6-digit email OTP codes or Google Sign-In. Saves JWT tokens in SecureStore and routes incomplete students directly to resume onboarding. | `POST /api/v1/auth/request-otp`<br>`POST /api/v1/auth/verify-email`<br>`POST /api/v1/auth/google`<br>`POST /api/v1/auth/refresh` | `users`<br>`email_verification_otps`<br>`auth_sessions`<br>`auth_refresh_tokens` |
| **Onboarding** | A 6-step questionnaire for subjects, academics, goals, skill ratings, study habits, and learning goals. Checks server state to resume at the first incomplete step and saves answers to backend step endpoints. | `GET /api/v1/student/onboarding`<br>`PUT /api/v1/student/onboarding/*`<br>`POST /api/v1/student/onboarding/complete` | `student_profiles`<br>`student_subjects`<br>`student_exam_goals`<br>`student_learning_goals`<br>`taxonomy_nodes`<br>`exams`<br>`users` |
| **Practice Tests** | Practice session setup (by subject, topic, difficulty, question count), question runner with instant feedback, passage view, bookmarking, and score result with retry incorrect. | `GET /api/v1/student/practice/catalog`<br>`POST /api/v1/student/practice/sessions`<br>`GET /api/v1/student/practice/sessions/:id`<br>`PUT /api/v1/student/practice/sessions/:id/items/:itemId/answer`<br>`POST /api/v1/student/practice/sessions/:id/submit`<br>`GET /api/v1/student/practice/summary`<br>`PUT/DELETE /api/v1/student/bookmarks/:questionId` | `assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_attempt_items`<br>`question_bookmarks`<br>`question_revisions`<br>`taxonomy_nodes`<br>`exam_versions` |
| **Mock Exams** | Full-length simulation exam catalog, timed runner with question palette, section navigation, section submit, blind answer entry, and post-submission review. | `GET /api/v1/student/mock-exams`<br>`POST /api/v1/student/mock-exams/:id/attempts`<br>`GET /api/v1/student/mock-exams/attempts/:id`<br>`PUT /api/v1/student/mock-exams/attempts/:id/items/:itemId/answer`<br>`POST /api/v1/student/mock-exams/attempts/:id/sections/:sectionId/submit`<br>`POST /api/v1/student/mock-exams/attempts/:id/submit`<br>`GET /api/v1/student/mock-exams/attempts/:id/review`<br>`GET /api/v1/student/mock-exams/history` | `assessment_templates`<br>`assessment_template_versions`<br>`assessment_modules`<br>`assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_attempt_items` |
| **Timed Exams & Tests** | Centered header countdown timer (`ExamTimer`) for mock exams and timed practice sessions (5–180 min), with monotonic time tracking and background state recovery. | `POST /api/v1/student/practice/sessions` *(timed)*<br>`POST /api/v1/student/mock-exams/:id/attempts`<br>`GET /api/v1/student/mock-exams/attempts/:id` | `assessment_attempts`<br>`assessment_attempt_modules` |
| **Home (Student Hub)** | Aggregated Hub screen displaying personalized welcome, timezone-accurate practice streak, target exam countdown focus card, Quick Access, mock exam status highlight, and recent activity. | `GET /api/v1/student/home` | `users`<br>`student_exam_goals`<br>`user_exam_preferences`<br>`exams`<br>`assessment_attempts`<br>`question_bookmarks` |
| **Stats (Progress & Review)** | Progress dashboard with overall accuracy, subject mastery bars, full session history, mock exam history, and paginated review queues for incorrect and bookmarked questions. | `GET /api/v1/student/stats`<br>`GET /api/v1/student/stats/questions`<br>`GET /api/v1/student/mock-exams/history` | `assessment_attempts`<br>`assessment_attempt_items`<br>`question_bookmarks`<br>`taxonomy_nodes` |
| **Dashboard (App Shell)** | Persistent native tab navigator (`AppTabs`) housing Hub, Tests, Cards, Stats, and Profile tabs with smooth transitions and badge indicators. | `GET /api/v1/student/home`<br>`GET /api/v1/student/stats` | `users`<br>`student_profiles`<br>`assessment_attempts` |

## 2. Backend

| Feature | Explanation | API Endpoints | Database Tables |
|---|---|---|---|
| **Sign Up** | Validates registration data with Zod schemas and prevents duplicate emails per audience with partial indexes. Stores exam preferences for mobile users and creates staff accounts in pending status. | `POST /api/v1/auth/register`<br>`POST /api/v1/admin/auth/register` | `users`<br>`user_exam_preferences` |
| **Login** | Verifies OTP codes, Google identity tokens, or Argon2id passwords with single-use refresh token rotation. Isolates mobile and admin credentials, and blocks pending or disabled accounts. | `POST /api/v1/auth/request-otp`<br>`POST /api/v1/auth/verify-email`<br>`POST /api/v1/auth/google`<br>`POST /api/v1/admin/auth/login`<br>`POST /api/v1/auth/refresh`<br>`POST /api/v1/admin/auth/refresh` | `users`<br>`email_verification_otps`<br>`auth_sessions`<br>`auth_refresh_tokens` |
| **Onboarding** | Enforces ordered step progression by locking profile rows in transactions and rejecting skipped steps. Saves answers into dedicated relational tables and records the completion timestamp on the user account. | `GET /api/v1/student/onboarding`<br>`PUT /api/v1/student/onboarding/subjects`<br>`PUT /api/v1/student/onboarding/academic`<br>`PUT /api/v1/student/onboarding/goals`<br>`PUT /api/v1/student/onboarding/skill-levels`<br>`PUT /api/v1/student/onboarding/study-preferences`<br>`POST /api/v1/student/onboarding/complete` | `student_profiles`<br>`student_subjects`<br>`student_exam_goals`<br>`student_learning_goals`<br>`taxonomy_nodes`<br>`exams`<br>`users` |
| **Practice Tests** | Validates candidate criteria, picks published question revisions, randomizes questions and options with Fisher-Yates, enforces atomic answer locking, scores attempts, and manages question bookmarks. | `GET /api/v1/student/practice/catalog`<br>`POST /api/v1/student/practice/sessions`<br>`GET /api/v1/student/practice/sessions/:id`<br>`PUT /api/v1/student/practice/sessions/:id/items/:itemId/answer`<br>`POST /api/v1/student/practice/sessions/:id/submit`<br>`GET /api/v1/student/practice/summary`<br>`PUT/DELETE /api/v1/student/bookmarks/:questionId` | `assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_attempt_items`<br>`question_bookmarks`<br>`questions`<br>`question_revisions`<br>`question_options`<br>`taxonomy_nodes`<br>`exam_versions` |
| **Mock Exams** | Dual-module engine for admin exam paper management (`/admin/mock-exams`) and student execution (`/student/mock-exams`). Snapshots revisions, enforces section locking, and yields post-submit reviews without answer leaks. | `GET /api/v1/admin/mock-exams`<br>`POST /api/v1/admin/mock-exams`<br>`PATCH /api/v1/admin/mock-exams/:id`<br>`POST /api/v1/admin/mock-exams/:id/publish`<br>`GET /api/v1/student/mock-exams`<br>`POST /api/v1/student/mock-exams/:id/attempts`<br>`GET /api/v1/student/mock-exams/attempts/:id`<br>`PUT /api/v1/student/mock-exams/attempts/:id/items/:itemId/answer`<br>`POST /api/v1/student/mock-exams/attempts/:id/submit`<br>`GET /api/v1/student/mock-exams/attempts/:id/review` | `assessment_templates`<br>`assessment_template_versions`<br>`assessment_modules`<br>`assessment_module_questions`<br>`assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_attempt_items`<br>`question_revisions` |
| **Timed Exams & Tests** | Server-owned timing engine using `clock.ts`. Manages lazy expiry settlement on read/write, 5-second network grace period (`acceptsAnswers`), and overall vs section-based deadline enforcement. | `POST /api/v1/student/practice/sessions`<br>`POST /api/v1/student/mock-exams/:id/attempts`<br>`GET /api/v1/student/mock-exams/attempts/:id`<br>`POST /api/v1/admin/mock-exams` | `assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_template_versions` |
| **Home (Student Hub)** | Single-call aggregator (`HomeService`) that concurrently fetches profile, primary exam, target score, timezone-aware practice streak, unfinished attempts, and recent scores via `Promise.all`. | `GET /api/v1/student/home` | `users`<br>`student_exam_goals`<br>`user_exam_preferences`<br>`exams`<br>`assessment_attempts`<br>`question_bookmarks`<br>`assessment_attempt_items` |
| **Stats (Progress & Review)** | Aggregates question attempts into global accuracy and subject breakdown (active subjects only), reuses `PracticeService` for session history, and filters review lists using `DISTINCT ON` for mistake resolution. | `GET /api/v1/student/stats`<br>`GET /api/v1/student/stats/questions`<br>`GET /api/v1/student/mock-exams/history` | `assessment_attempts`<br>`assessment_attempt_items`<br>`question_bookmarks`<br>`taxonomy_nodes`<br>`question_revisions`<br>`question_options` |
| **Dashboard** | Powers administrative authentication and identity verification (`GET /admin/auth/me`), permission guards (`AdminRoleGuard`), session revocation, and student overview data feeds. | `GET /api/v1/admin/auth/me`<br>`POST /api/v1/admin/auth/logout`<br>`GET /api/v1/student/home`<br>`GET /api/v1/student/stats` | `users`<br>`auth_sessions`<br>`auth_refresh_tokens`<br>`student_profiles`<br>`assessment_attempts` |

## 3. Web App

| Feature | Explanation | API Endpoints | Database Tables |
|---|---|---|---|
| **Sign Up** | Multi-step browser registration that matches the mobile app flow for students and parents. Holds step answers in a client draft context and sends to the backend through the web app API handler. | `/api/auth/register`<br>*(proxies to NestJS `POST /api/v1/auth/register`)* | `users`<br>`user_exam_preferences` |
| **Login** | Email OTP and Google login using a Backend-for-Frontend (BFF) proxy route. Transferred session tokens are placed in httpOnly cookies, preventing browser JavaScript from seeing raw tokens. | `/api/auth/request-otp`<br>`/api/auth/verify-email`<br>`/api/auth/google`<br>`/api/auth/logout`<br>*(proxied to NestJS `/api/v1/auth/*`)* | `users`<br>`email_verification_otps`<br>`auth_sessions`<br>`auth_refresh_tokens` |
| **Onboarding** | Desktop web 6-step wizard with resume detection, validation on each step, and route guards. Saves student selections via TanStack Query mutations to onboarding proxy routes. | `/api/student/onboarding/*`<br>`/api/student/onboarding/complete`<br>*(proxied to NestJS `/api/v1/student/onboarding/*`)* | `student_profiles`<br>`student_subjects`<br>`student_exam_goals`<br>`student_learning_goals`<br>`taxonomy_nodes`<br>`exams`<br>`users` |
| **Practice Tests** | Split-pane question runner with independent passage scrolling, keyboard shortcuts (A–E, arrow keys), setup wizard, live bookmarking, and post-test review via BFF proxy. | `/api/student/practice/*`<br>`/api/student/bookmarks/*`<br>*(proxied to NestJS `/api/v1/student/practice/*`)* | `assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_attempt_items`<br>`question_bookmarks` |
| **Mock Exams** | Full-screen test page (`/mock-exams/[attemptId]`) with centered top-bar countdown, left question rail, blind answer selection, submit dialog, and comprehensive answer review. | `/api/student/mock-exams/*`<br>*(proxied to NestJS `/api/v1/student/mock-exams/*`)* | `assessment_templates`<br>`assessment_attempts`<br>`assessment_attempt_modules`<br>`assessment_attempt_items` |
| **Timed Exams & Tests** | Top-bar countdown component (`ExamTimer`) for mock exams and timed practice sessions, calculating remaining time against monotonic client timestamps (`deadlineAt`). | `/api/student/mock-exams/*`<br>`/api/student/practice/*` | `assessment_attempts`<br>`assessment_attempt_modules` |
| **Home (Student Hub)** | Responsive web landing dashboard at `/hub` showing welcome banner, streak pill, exam countdown focus card, quick launch actions, mock exam card, and recent practice sessions. | `/api/student/home`<br>*(proxied to NestJS `/api/v1/student/home`)* | `users`<br>`student_exam_goals`<br>`assessment_attempts` |
| **Stats (Progress & Review)** | Web analytics dashboard at `/stats` featuring accuracy metric tiles, subject performance bars, practice test history, mock exam history, and tabbed review question tables. | `/api/student/stats`<br>`/api/student/stats/questions`<br>`/api/student/mock-exams/history`<br>*(proxied to NestJS `/api/v1/student/*`)* | `assessment_attempts`<br>`assessment_attempt_items`<br>`question_bookmarks` |
| **Dashboard (App Shell)** | Desktop sidebar and mobile header/bottom tabs wrapper (`AppShell`) featuring brand logo, user menu with sign out, theme toggle, and route protection. | `/api/student/home`<br>`/api/auth/logout` | `users`<br>`auth_sessions` |

## 4. Admin Panel

| Feature | Explanation | API Endpoints | Database Tables |
|---|---|---|---|
| **Sign Up** | Registration form for staff to submit their name, email, phone, and password for admin privileges. Accounts are marked pending upon creation and cannot log in until approved by an administrator. | `POST /api/v1/admin/auth/register` | `users` |
| **Login** | Email and password sign-in for approved staff, storing access tokens in memory and refresh tokens in localStorage. Displays an informative pending message if unapproved and auto-refreshes tokens on 401. | `POST /api/v1/admin/auth/login`<br>`POST /api/v1/admin/auth/refresh`<br>`POST /api/v1/admin/auth/logout`<br>`GET /api/v1/admin/auth/me` | `users`<br>`auth_sessions`<br>`auth_refresh_tokens` |
| **Onboarding (Taxonomy Data)** | The admin panel has no student onboarding; it manages the underlying taxonomy data that drives it. Administrators create, rename, reorder, and archive exam subjects and categories for mobile and web. | `GET /api/v1/admin/taxonomy`<br>`POST /api/v1/admin/taxonomy/nodes`<br>`PATCH /api/v1/admin/taxonomy/nodes/:id` | `taxonomy_nodes`<br>`exams`<br>`users` |
| **Practice Tests (Question Content)** | Content management interface for authoring questions, stems, answer options, taxonomy subjects, categories, and bulk CSV/Excel import that supply practice tests. | `GET /api/v1/admin/questions`<br>`POST /api/v1/admin/questions`<br>`PATCH /api/v1/admin/questions/:id`<br>`POST /api/v1/admin/questions/bulk`<br>`GET /api/v1/admin/taxonomy` | `questions`<br>`question_revisions`<br>`question_options`<br>`taxonomy_nodes`<br>`passages` |
| **Mock Exams** | Complete exam builder (`/exams`) to assemble papers from published questions, configure overall or section timing, preview papers, manage drafts, and publish/unpublish live papers. | `GET /api/v1/admin/mock-exams`<br>`POST /api/v1/admin/mock-exams`<br>`GET /api/v1/admin/mock-exams/:id`<br>`PATCH /api/v1/admin/mock-exams/:id`<br>`POST /api/v1/admin/mock-exams/:id/publish`<br>`POST /api/v1/admin/mock-exams/:id/unpublish`<br>`DELETE /api/v1/admin/mock-exams/:id` | `assessment_templates`<br>`assessment_template_versions`<br>`assessment_modules`<br>`assessment_module_questions` |
| **Timed Exams & Tests** | Timing configuration interface supporting single overall exam timers or separate section-based timers, with duration presets (30, 45, 60, 90, 120 mins) or custom inputs. | `POST /api/v1/admin/mock-exams`<br>`PATCH /api/v1/admin/mock-exams/:id` | `assessment_template_versions`<br>`assessment_modules` |
| **Home (Content Source)** | Admin does not display a student home screen; administrators manage the taxonomy nodes and exam definitions that dynamically generate targets and countdowns on the student Hub. | `GET /api/v1/admin/taxonomy`<br>`GET /api/v1/admin/mock-exams` | `taxonomy_nodes`<br>`exams`<br>`assessment_templates` |
| **Stats (Taxonomy Hierarchy)** | Admin taxonomy management defines the subject groupings, domain categories, and difficulty levels used to categorize student performance metrics. | `GET /api/v1/admin/taxonomy` | `taxonomy_nodes` |
| **Dashboard** | Core administrative portal frame (`DashboardLayout`) featuring fixed left navigation rail, operational greeting page (`DashboardPage`), staff profile header, and logout control. | `GET /api/v1/admin/auth/me`<br>`POST /api/v1/admin/auth/logout`<br>`GET /api/v1/admin/mock-exams`<br>`GET /api/v1/admin/taxonomy` | `users`<br>`auth_sessions`<br>`assessment_templates`<br>`taxonomy_nodes` |
